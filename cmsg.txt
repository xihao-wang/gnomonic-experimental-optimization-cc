feat: add projection boundary overlays and restructure VIS config node

Visualization parameters are now consolidated under a single sub-node
METRICS_EVALUATION.VIS (ENABLE, IOU_THRESHOLD, PROJ_BOUNDARY_COLORS),
and SINGLE_CONFIG_RUN is nested under METRICS_EVALUATION for a clean,
consistent hierarchy.

Projection boundaries are now drawn on every fisheye visual: each gnomonic
sub-view's FOV outline is rendered in alternating colors (rose / light cyan
by default, cycling across projections), giving an immediate spatial
understanding of which detection came from which sub-view.

Modified:
  evaluation/lib/config.py
    - Removed flat ENABLE_VISUALS and VIS_IOU_THRESHOLD from METRICS_EVALUATION
    - Added METRICS_EVALUATION.VIS sub-node with ENABLE, IOU_THRESHOLD,
      PROJ_BOUNDARY_COLORS (RGB tuples, default rose + light cyan)
    - Moved SINGLE_CONFIG_RUN inside METRICS_EVALUATION

  evaluation/run_single_config.py
    - Updated to use METRICS_EVALUATION.VIS.* config paths
    - Passes proj_boundary_colors to SingleConfigRunner

  evaluation/run_metrics_evaluation.py
    - Updated to use METRICS_EVALUATION.VIS.* config paths
    - Passes proj_boundary_colors to MetricsEvaluatorRunner

  evaluation/lib/single_config_runner.py
    - Added proj_boundary_colors param to __init__
    - Imports draw_fov_on_fisheye from image_composer.multi_persp
    - Added _draw_projection_boundaries(): chains draw_fov_on_fisheye calls
      with alternating BGR colors (converted from RGB config values)
    - Called in _save_visuals() before GT/TP/FP/FN bbox drawing

  evaluation/lib/metrics_evaluator_runner.py

    - _save_visuals() gains projection_config param; boundaries drawn on
